AgentHUD · Hook 状态机

Claude Code / Codex 的生命周期事件如何变成浮窗里的状态

一、数据流

① Hook 触发agent 每个生命周期事件（提交提问 / 需批准 / 结束）调用 spool.py，把事件 JSON 从 stdin 传入
→
② spool.py 追加归一化成一行 JSON，O_APPEND 写入 ~/.ag_notifier/events.jsonl。追加即走，绝不阻塞 agent
→
③ AgentHUD 实时读tail 这个文件，按 tool/session_id 聚合，跑下面这台状态机，驱动浮窗 + 菜单栏 + 通知

二、四个状态

running 运行中
蓝色呼吸 · agent 正在干活
waiting 等待你
红色闪烁 · 需要你输入/批准
done 已完成
绿色常亮 · 这一轮跑完了
stale 无响应
灰色变淡 · running 太久没动静

三、状态机（事件驱动 + 时间驱动）

四、事件 → 状态 映射

语义Claude Code 事件Codex 事件结果状态
提交提问 / 开始一轮 UserPromptSubmit UserPromptSubmit running
工具调用后（心跳） PostToolUse PostToolUse running · 刷新，长回合不变灰
需要批准 / 等你输入
（含 plan 呈现等批准）		 PermissionRequest · Notification PermissionRequest waiting
一轮结束 Stop Stop done

⚠️ 故意不用 Claude 的 SessionStart：它会给每个后台/恢复的会话都标「运行中」，制造大量幽灵任务。只有你真正发消息（UserPromptSubmit）才算开始。

💡 Plan 模式：Claude 呈现 plan 等你批准时只触发 PermissionRequest（Stop 和 Notification 都不发——是 Claude Code 已知缺口），靠它点亮红灯「等你」。PostToolUse 当心跳，让长回合（>2 分钟）不被误判成灰。

五、时间规则（自动转移，无需事件）

  • running 闲置 120 秒 没有任何新事件 → 变 stale（灰，可能终端被关/进程被杀，Stop 没发出来）。
  • running / stale 闲置 15 分钟 → 自动移除（彻底从列表消失，防止积压）。
  • done → 一直保留，直到你点击该任务或菜单选「清除已完成」才消失。
  • waiting → 一直保留，直到你处理（回复后转 running，或它结束转 done）。
  • 收到任何新事件 → lastUpdate 刷新，stale 立即「复活」回 running。

六、聚合与过滤

  • 聚合键 = tool / session_id。同一会话的新事件覆盖旧状态（最新状态生效）。
  • 噪音过滤：cwd 为空、或正好等于家目录的会话不显示（桌面 app 的后台内部会话，否则会显示成用户名 “raf”）。
  • 项目名 = cwd 末级目录；摘要行 = 该会话最近一次 UserPromptSubmit 的提问。

spool 行格式：

{"ts":1780000000.0,"tool":"claude","state":"running","session_id":"a1b2…","cwd":"/Users/raf/Desktop/agents/courseweb","event":"UserPromptSubmit","prompt":"修复支付回调超时"}

AgentHUD · 阈值（120s / 15min）可在 Sources/AgentNotifier/TaskStore.swift 调整 · 事件映射在 ~/.claude/settings.json 与 ~/.codex/config.toml
